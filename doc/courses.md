# Course management

The reference of `CourseService`. The README keeps its overview, with a short example: [`CourseService`](../README.md#courseservice).

## `CourseService`

A teacher manages each of their courses (a "vak") in Smartschool through its modules: its documents (Documenten), its upload zones (Uploadzone), where pupils hand in files, and its news (Vaknieuws). The service reads the courses of the course menu, and reads and adds to those three modules of a course.

A course is a `ManagedCourse` of the course menu in the top bar: its `id` is the `courseID` and its `platformId` the `ssID` that every module of the course takes. It is not a course of the Lesfiches module's course list (`LessonContentService.getCourses`): a course made in the course management (`/course/course-management`) was in the course menu but not in that list (seen live, 2026-11-23).

### Methods

| Method | Returns | Description |
|---|---|---|
| `getCourses()` | `Future<List<ManagedCourse>>` | The courses of the course menu (`POST /Topnav/getCourseConfig`): the own courses, then those of the classes the user is the titular of, then those of the school community (`ManagedCourse.kind`), each in the menu's order, with `id`, `platformId`, `name`, `description` (`descr`, often its classes) and `teacher`. An entry without a numeric `id` and `platformId` is left out. |
| `getDocuments(course, folderId: 0)` | `Future<List<CourseDocument>>` | The items of a folder of the course's documents (`0`: the top), as its management page lists them: `id`, `name`, `kind` (`folder`, `file` or `other`, such as a document made in Smartschool's editor), `downloadPath` of a file, `isVisible`, and `visibleFrom` / `visibleUntil` as the list writes them (`null` for `-`). A page without a list (a folder the user cannot manage) is a `SmartschoolCourseError`. |
| `createFolder(course, name: ..., parentId: 0, description: '', visible: true, visibleFrom: null, visibleUntil: null)` | `Future<CourseDocument>` | Makes a folder in a folder of the documents and returns it as the list shows it after the save. A blank name, or one Smartschool does not allow (`SmartschoolUploader`'s rule: none of `/ : * ? " \ < > |`, no dot at its start or end), and an end before the start are an `ArgumentError`, before anything is sent. |
| `uploadDocuments(course, filePaths, folderId: 0, visible: true, visibleFrom: null, visibleUntil: null, notify: false)` | `Future<List<CourseDocument>>` | Uploads files into a folder of the documents, each under its own name, and returns them as the list shows them after the save, in the order given. `notify` sends the pupils a notification, as "Opslaan en melden" does. No files, a file that does not exist, a name Smartschool does not allow and two files of the same name are an `ArgumentError`, before anything is sent; a failed upload of a file a `SmartschoolAttachmentUploadError` (nothing is saved then). |
| `downloadDocument(document, maxBytes: null)` | `Future<Uint8List>` | Downloads a file of the documents (`SmartschoolClient.download` of its `downloadPath`). Another item is an `ArgumentError`. |
| `getUploadZones(course)` | `Future<List<CourseUploadZone>>` | The upload zones of the course, in the order of the module's tree, each with its `id` (`mapID`), `name` and `path` (the names of the folders of the tree it is in). |
| `createUploadZone(course, name: ..., description: '', visibleFrom: null, visibleUntil: null, maxFiles: null, visible: true, classmatesSee: false, classmatesRead: false, pupilsReadOwn: true)` | `Future<CourseUploadZone>` | Makes an upload zone at the top of the module's tree and returns it as the tree shows it after the save. `visibleFrom` and `visibleUntil` (both or neither) limit when pupils can upload; `maxFiles` how many files a pupil uploads; `classmatesSee` and `classmatesRead` let pupils see and read each other's files; `pupilsReadOwn` lets a pupil read their own files (the module's default). A blank name, only one date, an end before the start, `maxFiles` below 1 and a value with `]]>` are an `ArgumentError`, before anything is sent. |
| `getNews(course)` | `Future<List<CourseNewsItem>>` | The news items of the course, in the order of its management list: `id`, `title`, `isVisible`, `visibleFrom` / `visibleUntil`, and `html`, the message as the news page shows it (`null` for an item pupils do not see, which the news page leaves out). |
| `postNews(course, title: ..., html: ..., visible: true, notify: false)` | `Future<CourseNewsItem>` | Posts a news item with the message `html` and returns it as the list shows it after the save. A blank title is an `ArgumentError`, before anything is sent. |

### Writes

Each write reads the list first (the folder, the tree of the upload zones, the news), sends its save **once**, never again after logging in, and reads the list again: the write is confirmed by an item that was not in the list before, with the name sent. A save that went out but is not confirmed (another answer than the one expected, a dropped connection, a list after it that cannot be read or does not show the new item) is a `SmartschoolCourseWriteUnconfirmedError`, with the `statusCode` or the `cause`: read the list before trying again, as a second save makes a second item. A refused session before the save went out is a `SmartschoolSessionExpiredError`: nothing was sent.

Dates go out as the modules' date fields take them, `YYYY-MM-DD HH:MM`, in local time.

### What Smartschool answers

Seen live on 2026-11-23, in a course made for testing:

- **The course menu** (`POST /Topnav/getCourseConfig`) is JSON with `courseFilters`, the courses in `own`, `titu` and `community` (each `{id, platformId, name, descr, icon, url, teacher}`, with `url` `/planner/course/courseID/{id}/ssID/{platformId}`), `favourites` and `courseManagementLink`.
- **The documents.** A folder's management page is `/Documents/Admin/Index/courseID/{c}/parentID/{folder}/ssID/{s}` (`0` is the top; the pupils' view is `/Documents/Index/Index/courseID/{c}/ssID/{s}`). It holds a `ul#list` with an `li itemID="{id}"` per item: a link `a.smsc_cm_link` with the name, to the folder's own page for a folder and to `/Documents/Download/Index/htm/0/courseID/{c}/docID/{id}/ssID/{s}` for a file; a visibility icon `div.ico.visible` or `div.ico.not_visible` with the ID `visibleImg{id}`; and `div.from` / `div.until` with the dates, `-` for none. The menu "Voeg toe" (`POST /Documents/Admin/getaddbutton`) names the forms: a new folder (`/Documents/Map/Index/...`), a new document of the editor (`/Documents/File/Index/...`), one file (`/Documents/Upload/Index/...`) and several files (`/Documents/Multiupload/Index/...`).
- **A new folder** is the form of `Map/Index`, posted form-encoded to `/Documents/Map/Save/courseID/{c}/ssID/{s}` with `parentID`, `name`, `description`, `visible` (`1` or `0`), and `fromdatecheck` (`1`) with `fromdate`, `untildatecheck` (`1`) with `untildate`. It is answered with `302` and no body; the answer does not name the folder.
- **Several files** take the form of `Multiupload/Index`, which holds the hidden `randomDir`: an upload directory of the session the form was loaded in. The files are uploaded into it as for a message (`SmartschoolUploader`, `POST /Upload/Upload/Index`, answered `true`); the form lists them (`POST /Documents/Multiupload/Showfiles/randomDir/{dir}/ssID/{s}/courseID/{c}`). The save posts `randomDir`, `parentID`, `visible`, the date fields and `sendNotification` (`0`, or `1` for "Opslaan en melden") to `/Documents/Multiupload/Save/courseID/{c}/parentID/{folder}/ssID/{s}`, answered with `302`. The upload and the save are sent in the session of the form only.
- **The upload zones** are listed by the module's tree, `POST ?module=Uploadzone&file=tree&ssID={s}&courseID={c}` with `id=0`: JSON nodes `{attributes: {id, rel, clickurl}, data: {title, icon}, children, hasChildren}`, the root `tree_0` and an upload zone `uploadmap_{id}` (`rel` `uploadmap`). A new one is the dispatcher command `uploadzone` / `saveuploadmap` (`POST ?module=Uploadzone&file=dispatcher&function=dispatcher`, form-encoded `command`, the XML command format of the Messages dispatcher) with the params `courseID`, `ssID`, `naam`, `omschrijving`, `parentID`, `tijd` (`0` unlimited, `1` the period `vanDatum` to `totDatum`), `aantal` (the most files a pupil uploads, empty for no limit), `zichtbaar`, `medezien`, `medelezen`, `eigenlezen`, `files_sort`, `user_group`, `shareteacher` and `students_showdefault`, as the module's form (`edituploadmap`) sends them; it is answered with `<status>ok</status>` and the commands `edituploadmapdone` and `dojavascript`.
- **The news.** The management list (`?module=News&file=coursenews_admin&courseID={c}&ssID={s}`) holds a `ul#list` with an `li itemID="{newsID}"` per item, with the title (in the `title` of `div.name`), a visibility icon as the documents', and the dates. The news page (`?module=News&file=coursenews&function=main&...`) shows the items pupils see, each with its title and its message in `div.smsc_cm_body_row_block_desc`, and a link "Snel wijzigen" with its `newsID`. A new item is the form of `?module=News&file=addNews&courseID={c}&ssID={s}` (an editor for the message), posted form-encoded to the same URL with `store` (`1`), `sendNotification`, `title`, `message` (HTML) and `visible` (`1`; left out to hide it); it is answered with `302` to the management list. Text went in as UTF-8 (`é` kept); the message was kept as it was sent.
